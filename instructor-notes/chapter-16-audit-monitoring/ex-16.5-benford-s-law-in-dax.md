## Purpose and learning outcomes

Chapter 8 tested the first digits of supplier payments in a workbook and found that the partial payments, not the payments as a whole, departed from Benford's Law. The audit committee wants the test on the monitoring report as the anomaly layer beside the rule tests. The exercise builds it in DAX and then asks whether the departure is an exception or an anomaly. The analytics type is diagnostic, with a statistical test.

Students can:

- load payments through a date and classify each as full or partial (Requirement 1);
- take the first significant digit in a calculated column and say why the text of the amount fails (Requirement 2);
- build a disconnected table of expected shares and measures for the observed share and the mean absolute deviation (Requirement 3);
- show observed against expected by digit and record the deviation for three groups (Requirement 4);
- classify each result with Chapter 8's ranges and separate an anomaly from an exception (Requirement 5).

**Competencies practiced.** CPA Evolution Core S2 M9 (audit procedures and audit data analytics) and BAR M10 (advanced data analytics and dashboards); IMA Data Analytics and Insights (statistical analysis, data tools and techniques); IFAC IES 2 (f) (audit) and (i) (using ICT to analyze data); AACSB A5 part 5.1, with part 5.3 when the instructor adds an independent-learning task.

## Step-by-step solution

### Requirement (1): The payments

**Step 1. Import, filter and classify.**

a. Choose **Home > Get data > Excel workbook**, select T39_DisbursementPayment and choose **Transform Data**. Rename it `Payments`, keep the columns the exercise names, set PaymentDate to **Date**, and filter it to the as-of date or earlier.
b. Import T37_PurchaseInvoice as `PaymentInvoices`, keep PurchaseInvoiceID and GrandTotal, and clear **Enable load**.
c. In Payments, merge PaymentInvoices on PurchaseInvoiceID, expand GrandTotal, and add `PaymentKind` with the formula below the filter in the block.

```
    #"Filtered Rows" = Table.SelectRows(#"Changed Type1", each [PaymentDate] <= #date(2026, 12, 31)),
    #"Added Custom" = Table.AddColumn(#"Expanded PaymentInvoices", "PaymentKind", each if [Amount] = [GrandTotal] then "Full" else if [Amount] < [GrandTotal] then "Partial" else null),
```

**Check:** 39,864 payments, 34,115 Full and 5,749 Partial. An exact comparison of Amount with GrandTotal splits them as a half-cent tolerance does on this data. **Watch for:** the date filter. Without it the query holds 40,127 payments, the 263 payments dated in 2027 included.

### Requirement (2): The first digit

**Step 2. Add the column.**

a. In **Report view**, select Payments and choose **Modeling > New column**.
b. Enter the formula below and set the column not to summarize.

```
FirstDigit = VALUE ( LEFT ( FORMAT ( Payments[Amount], "0.00000000E+00" ), 1 ) )
```

**Check:** every payment has a digit from 1 to 9. The scientific notation puts the first significant digit first, whatever the size. **Watch for:** two shortcuts. The text of the amount fails on the 121 payments below one dollar, whose text begins with 0: digit 0 is not in the table of digits, so they sit in the denominator and in no digit, the shares add to 99.70%, and the deviation reads 0.01283 in place of 0.01295. That lands in the same class, so only the check on digit 0 shows it. A format that rounds to a whole number first, as Chapter 8's `TEXT(x, "0")` did, gives 673 payments another digit, 55 of them 0.

### Requirement (3): The digits and the measures

**Step 3. Build the table and the measures.**

a. Choose **Modeling > New table** and enter the table below. Do not relate it to any table.
b. Select **Key Measures**, add the three measures, and type `Ex 16.5` in **Display folder** in **Model view**.

```
Digits =
ADDCOLUMNS (
    SELECTCOLUMNS ( GENERATESERIES ( 1, 9, 1 ), "Digit", [Value] ),
    "Expected Share", LOG10 ( 1 + 1 / [Digit] )
)
```

```
Observed Share =
VAR Digit = SELECTEDVALUE ( Digits[Digit] )
RETURN
    DIVIDE ( CALCULATE ( COUNTROWS ( Payments ), Payments[FirstDigit] = Digit ), COUNTROWS ( Payments ) )
Benford Share = SELECTEDVALUE ( Digits[Expected Share] )
Benford MAD =
CALCULATE (
    AVERAGEX ( VALUES ( Digits[Digit] ), ABS ( [Observed Share] - [Benford Share] ) ),
    REMOVEFILTERS ( Digits )
)
```

**Check:** nine rows; the expected shares add to one. **Watch for:** a deviation measure without REMOVEFILTERS ( Digits ). Select a digit on the chart and the table's deviation becomes that digit's alone, 0.02707 for digit 1 against 0.01295 for all nine. **Watch for:** a relationship between Digits and Payments. The denominator of Observed Share then shrinks to the payments with that digit, every digit reads `100%`, and the deviation reads 0.88889.

### Requirement (4): The page

**Step 4. Chart observed against expected.**

a. On a page named `Ex 16.5`, add a **Slicer** of PaymentKind, titled "PaymentKind".
b. Add a **Clustered column chart** with Digit on the **X-axis** and Observed Share and Benford Share on the **Y-axis**, titled "First digits of the payments: observed and Benford's expected share".
c. Add a **Table** of PaymentKind, Payments Counted and Benford MAD, titled "Mean absolute deviation by kind of payment".
d. Select the slicer, choose **Format > Edit interactions**, and click the **None** icon above the table.

**Check:** the deviation is 0.01295 for all payments, 0.00755 for 34,115 full payments and 0.04496 for 5,749 partial ones. **Watch for:** the interaction. If the slicer filters the table, choosing Partial leaves one row and the all-payments figure disappears.

### Requirement (5): The classification

**Step 5. Classify and interpret.** All payments are marginally acceptable, full payments acceptable and partial payments a nonconformity. The partial payments' departure is an anomaly, not an exception: no rule fails and no document is flagged. It plausibly reflects the payment policy, because only invoices of a thousand dollars or more are paid in parts, a selection by size that can distort the digits. It calls for a look at which invoices and suppliers are paid in parts, not for an accusation, and a digit test cannot show that the payments are genuine.

**Instructor check.** In **DAX query view**, run this and compare it with the Expected results.

```dax
EVALUATE ROW ( "MAD, partial payments", ROUND ( CALCULATE ( [Benford MAD], Payments[PaymentKind] = "Partial" ), 5 ), "Payments with digit 0", CALCULATE ( [Payments Counted] + 0, Payments[FirstDigit] = 0 ), "Payments whose text begins with 0", COUNTROWS ( FILTER ( Payments, LEFT ( Payments[Amount], 1 ) = "0" ) ) )
```

Taking the first character of the amount as text fails on the 121 payments below \$1, whose text begins with 0. The observed share is a count of the payments with the digit divided by the count of all payments in the filter context; MAD = AVERAGEX of the nine absolute differences inside CALCULATE ( ..., REMOVEFILTERS ( Digits ) ), so a digit selected on the page cannot narrow it to one digit's deviation. Nickell, Schwebke, and Goldwater (2023) is a Power BI and Benford teaching case.

## What a strong answer says

- **(2)** The text of an amount below one dollar begins with 0, so the digit is wrong; scientific notation starts with the first significant digit.
- **(5)** The three classifications with their values, the policy that plausibly explains the partial payments, and the next step: look at the invoices and suppliers behind the partial payments. It cites Nickell, Schwebke and Goldwater (2023) as the same test in Power BI.

A strong answer calls the result an anomaly and names what to examine. A weak one calls it fraud or ignores it.

## Common mistakes and how to respond

- **Text of the amount.** *Symptom:* 121 payments with digit 0. *Response:* ask how a payment of fifty cents begins.
- **Rounded first.** *Symptom:* 673 payments with another digit. *Response:* ask what rounding does to 9.6.
- **Digits related to Payments.** *Symptom:* every digit at `100%`. *Response:* ask what the denominator now counts.
- **One digit's deviation.** *Symptom:* the table's deviation changes when a digit is selected. *Response:* ask how many digits the statistic should average.
- **No date filter.** *Symptom:* 40,127 payments. *Response:* ask which date the exercise sets.
- **The slicer on the table.** *Symptom:* one row. *Response:* ask which visuals a slicer should reach.
- **Fraud concluded.** *Symptom:* "partial payments are suspicious". *Response:* ask which invoices are paid in parts, and why.
