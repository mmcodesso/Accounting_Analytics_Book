## Purpose and learning outcomes

Tutorial 8.3 flagged journal entries with five tests in Excel and combined the flags into a risk score. The chief audit executive wants the same tests in a saved query that can be rerun on next year's entries, and wants proof that the SQL gives the workbook's results. The exercise turns each test into a CASE flag, so that one CTE holds the five tests and the score is a sum. Its traps are the ones the chapter warns about: a function that returns text, a date with a time, and an operator that truncates. The analytics type is diagnostic: the tests locate entries for follow-up.

By the end, students can:

- write each test as a CASE that returns 1 or 0, using `strftime` and `date` on a time-stamped date (outcomes 1 and 2);
- total the flags by test and by score, and reproduce an earlier workpaper's counts (outcome 1);
- rank the flagged entries for review and save the tests as a view (outcomes 3 and 5);
- say what a saved, reviewed query gives an auditor and what controls it still needs.

**Competencies practiced.** CPA Evolution Core S2 M5 (risk of fraud and noncompliance) and M9 (audit procedures, analytical procedures and audit data analytics); IMA Reporting and Control (internal control) and Data Analytics and Insights (data tools and techniques); IFAC IES 2 (f) and IES 4 (a); AACSB A5 parts 5.1 and 5.3.

## Step-by-step solution

### Requirement (1): The five flags

**Step 1. Join the approver and flag each test with CASE.** The flags sit in a Flags CTE, and the final SELECT counts the entries flagged by each test.

```sql
-- Requirements (1) and (2), step 1: the entries flagged by each test
-- Population: all 851 journal entries; expected: Tutorial 8.3's counts
WITH Flags AS (
    SELECT je.EntryNumber, je.EntryType, je.PostingDate, je.TotalAmount,
        CASE WHEN strftime('%w', je.CreatedDate) IN ('0', '6')
            THEN 1 ELSE 0 END AS Weekend,
        CASE WHEN date(je.CreatedDate) > je.PostingDate
            THEN 1 ELSE 0 END AS Backdated,
        CASE WHEN je.CreatedByEmployeeID = je.ApprovedByEmployeeID
            THEN 1 ELSE 0 END AS SelfApproved,
        CASE WHEN je.TotalAmount > COALESCE(e.MaxApprovalAmount, 0)
            THEN 1 ELSE 0 END AS AboveLimit,
        CASE WHEN je.TotalAmount = ROUND(je.TotalAmount / 1000, 0) * 1000
            THEN 1 ELSE 0 END AS RoundAmount
    FROM JournalEntry AS je
        LEFT JOIN Employee AS e ON e.EmployeeID = je.ApprovedByEmployeeID
)
SELECT COUNT(*) AS Entries, SUM(Weekend) AS Weekend,
    SUM(Backdated) AS Backdated, SUM(SelfApproved) AS SelfApproved,
    SUM(AboveLimit) AS AboveLimit, SUM(RoundAmount) AS RoundAmount
FROM Flags;
```

**Check:** one row, 851 entries with Weekend 17, Backdated 6, SelfApproved 7, AboveLimit 9, RoundAmount 4. **Watch for:** the wrong versions of three flags run without an error.

- `strftime('%w', CreatedDate) IN (0, 6)` flags 0, where the model flags 17: strftime returns text, and text never equals an integer.
- `CreatedDate > PostingDate` with no `date()` flags 851 entries, all of them, where the model flags 6: every CreatedDate has a time, so on the posting date itself the longer text is larger.
- `TotalAmount % 1000 = 0` flags 4, the same as the model, so it passes on this data. It is still wrong, because `%` truncates a real number to an integer first: `5000.5 % 1000` returns 0.0. The model script uses `TotalAmount = ROUND(TotalAmount / 1000, 0) * 1000`.

The model script joins the approver with LEFT JOIN and tests `COALESCE(e.MaxApprovalAmount, 0)`. An entry with no approver would count as above the limit. None is missing here, but a missing approver is better reported as a test of its own.

### Requirement (2): The score

**Step 2. Add the five flags and count the entries at each score.** A Scored CTE adds `Weekend + Backdated + SelfApproved + AboveLimit + RoundAmount` as RiskScore, and the final SELECT groups by it with the count and the total amount.

**Check:** 4 rows: score 0, 818 entries; score 1, 25 entries; score 2, 7 entries; score 4, 1 entry. No entry scores 3, so that row does not appear. A student who expects a row for every score should see why a GROUP BY lists only the scores that exist.

### Requirement (3): The comparison with Tutorial 8.3

**Step 3. Compare the counts.** Students lay the 5 test counts and the score counts beside their Excel results. **Check:** they agree exactly, because the tests are the same; if one differs, look first at Weekend and Backdated, which read a time-stamped date.

### Requirement (4): The entries to review

**Step 4. Rank the entries that score two or more.**

```sql
-- Requirement (4): the entries scoring 2 or more, ranked by score and amount
-- Population: the scored entries; expected: 8 entries, JE-2024-000001 first
WITH Flags AS (
    SELECT je.EntryNumber, je.EntryType, je.PostingDate, je.TotalAmount,
        CASE WHEN strftime('%w', je.CreatedDate) IN ('0', '6')
            THEN 1 ELSE 0 END AS Weekend,
        CASE WHEN date(je.CreatedDate) > je.PostingDate
            THEN 1 ELSE 0 END AS Backdated,
        CASE WHEN je.CreatedByEmployeeID = je.ApprovedByEmployeeID
            THEN 1 ELSE 0 END AS SelfApproved,
        CASE WHEN je.TotalAmount > COALESCE(e.MaxApprovalAmount, 0)
            THEN 1 ELSE 0 END AS AboveLimit,
        CASE WHEN je.TotalAmount = ROUND(je.TotalAmount / 1000, 0) * 1000
            THEN 1 ELSE 0 END AS RoundAmount
    FROM JournalEntry AS je
        LEFT JOIN Employee AS e ON e.EmployeeID = je.ApprovedByEmployeeID
),
Scored AS (
    SELECT *,
        Weekend + Backdated + SelfApproved + AboveLimit + RoundAmount
            AS RiskScore
    FROM Flags
)
SELECT RANK() OVER (ORDER BY RiskScore DESC, TotalAmount DESC)
        AS ReviewRank,
    EntryNumber, EntryType, PostingDate, TotalAmount, RiskScore,
    Weekend, Backdated, SelfApproved, AboveLimit, RoundAmount
FROM Scored
WHERE RiskScore >= 2
ORDER BY ReviewRank;
```

![A mock of the entries that score two or more, ranked for review, the list the audit senior opens first.](../figures/chapter-11-analytical-queries/IF-11-5-A.pdf)

**Check:** 8 rows, JE-2024-000001 first with a score of 4. **Watch for:** ranked by score alone, the 7 entries at the second score all tie at the same rank, so TotalAmount is the second key that makes the order useful. The WHERE on the score is safe in the same SELECT as the RANK, because the score is an ordinary column; it only means that the rank counts the flagged entries.

### Requirement (5): The view and the explanation

**Step 5. Save the tests as a view, and rerun it.** The model script drops `Ex11_5_JournalEntryTests` if it exists and creates it from the Scored CTE with no ORDER BY, then counts the flags and the entries scoring two or more from the view.

**Check:** the view returns 851 entries and the counts of Step 1. Students then write two or three sentences; see "What a strong answer says".

## What a strong answer says

- **Why the SQL agrees with the workbook.** The tests are the same; the counts are Tutorial 8.3's. A strong comparison names the one thing that needed care, the time in CreatedDate.
- **What a saved query gives an auditor.** One inspectable definition applied the same way to every entry, which a reviewer can read instead of sampling cells, and which avoids the copying errors of a formula filled down a column.
- **What it does not give.** A rerun needs the same source snapshot, query and parameters, and the query still depends on the completeness of the source and on its own logic, which must be tested. The view alone is not a fixed audit record, because it runs on whatever data the file holds.
- **The controls it needs.** Keep the output, the row counts and a reconciliation to the ledger with the workpaper, and put the query under change control.
- **A flag is not a finding.** The highest score belongs to the opening entry created by the chief financial officer, and the strong answer proposes follow-up, not a conclusion.

A weak explanation says the view proves the tests were applied.

## Common mistakes and how to respond

- **Weekend with integers.** *Symptom:* 0 entries. *Response:* ask what type strftime returns.
- **Backdated without `date()`.** *Symptom:* 851 entries. *Response:* ask what a time does to a text comparison.
- **RoundAmount with `%`.** *Symptom:* the right count on this data. *Response:* ask what `5000.5 % 1000` returns.
- **Ranking by score alone.** *Symptom:* 7 entries sharing a rank. *Response:* ask what orders entries with the same score.
- **A view taken as a record.** *Symptom:* an explanation with no mention of the data it runs on. *Response:* ask what changes next month.
- **A missing approver ignored.** *Symptom:* none here. *Response:* ask what an INNER JOIN does with an entry that has none.
