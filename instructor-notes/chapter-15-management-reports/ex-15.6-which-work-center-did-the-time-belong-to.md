## Purpose and learning outcomes

The plant page assigns each direct labor line to the work center of the operation it was charged to. The time clock records a work center too, and an auditor does not act on a work-center chart until the two records of the same fact have been compared. The exercise is a data-quality test built in Power Query and DAX, and it ties back to Chapter 12's finding that direct time is recorded after its operation ended. The analytics type is diagnostic, with the judgment that follows a test: say what each record can and cannot support.

Students can:

- import a second source for the same fact and merge it without losing lines (Requirements 1 and 2);
- write tests that return a blank when there is nothing to compare (Requirement 3);
- count disagreements by year and lay them out as a matrix (Requirement 4);
- compare shares on a named denominator, and relate the result to Chapter 12 (Requirement 5);
- decide which record answers which question (Requirement 6).

**Competencies practiced.** CPA Evolution Core S2 M8 (audit evidence and tests of controls) and ISC M4 (use and management of data); IMA Data Analytics and Insights (data literacy) and Reporting and Control (internal control); IFAC IES 2 (f) (audit) and IES 4 (a) (professional skepticism and professional judgment); AACSB A5 part 5.1.

## Step-by-step solution

### Requirement (1): The two paths

**Step 1. Import the operation and the clock entry.**

a. Choose **Home > Get data > Excel workbook**, select CharlesRiver.xlsx, and in the **Navigator** select **T52_WorkOrderOperation** and **T66_TimeClockEntry**. Click **Transform Data**.
b. Rename the queries `OperationPaths` and `ClockPaths`.
c. In OperationPaths, choose **Home > Choose Columns** to keep WorkOrderOperationID, WorkCenterID and ActualEndDate, and set ActualEndDate to **Date**. In ClockPaths, keep TimeClockEntryID and WorkCenterID.
d. Clear **Enable load** on both.

```m
// OperationPaths
    #"Removed Other Columns" = Table.SelectColumns(#"Changed Type",{"WorkOrderOperationID", "WorkCenterID", "ActualEndDate"}),
    #"Changed Type1" = Table.TransformColumnTypes(#"Removed Other Columns",{{"ActualEndDate", type date}})
```

```m
// ClockPaths
    #"Removed Other Columns" = Table.SelectColumns(#"Changed Type",{"TimeClockEntryID", "WorkCenterID"})
```

**Check:** two small queries that feed the third and do not load.

### Requirement (2): The merges

**Step 2. Import the labor lines and merge each path.**

a. Import **T60_LaborTimeEntry** as `LaborPaths` and keep LaborTimeEntryID, WorkOrderOperationID, TimeClockEntryID, WorkDate, LaborType, RegularHours and OvertimeHours. Set WorkDate to **Date**.
b. Choose **Home > Merge Queries** and merge with OperationPaths on WorkOrderOperationID, with a left outer join. Expand WorkCenterID and ActualEndDate without the prefix, and rename WorkCenterID `OperationWorkCenterID`.
c. Merge with ClockPaths on TimeClockEntryID the same way, expand WorkCenterID, and rename it `ClockWorkCenterID`.
d. Merge each of the two keys with the **WorkCenter** query to bring the name, as `OperationWorkCenter` and `ClockWorkCenter`.

```m
    #"Merged Queries" = Table.NestedJoin(#"Changed Type1", {"WorkOrderOperationID"}, OperationPaths, {"WorkOrderOperationID"}, "OperationPaths", JoinKind.LeftOuter),
    #"Expanded OperationPaths" = Table.ExpandTableColumn(#"Merged Queries", "OperationPaths", {"WorkCenterID", "ActualEndDate"}, {"WorkCenterID", "ActualEndDate"}),
    #"Merged Queries2" = Table.NestedJoin(#"Renamed Columns", {"TimeClockEntryID"}, ClockPaths, {"TimeClockEntryID"}, "ClockPaths", JoinKind.LeftOuter),
    #"Expanded ClockPaths" = Table.ExpandTableColumn(#"Merged Queries2", "ClockPaths", {"WorkCenterID"}, {"WorkCenterID"}),
```

**Check:** LaborPaths keeps all 68,859 lines, because every merge is a left outer join; a line with no match keeps a null.

**Watch for:** an inner join. LaborPaths then holds 51,097 lines: the indirect and non-manufacturing lines, and the direct lines with no operation, are gone, and Requirement (6) has no indirect hours to place.

### Requirement (3): The two tests

**Step 3. Add the custom columns.** Choose **Add Column > Custom Column** twice, and set both to a true or false type.

```m
    #"Added Custom" = Table.AddColumn(#"Renamed Columns1", "SameWorkCenter", each if [OperationWorkCenter] = null or [ClockWorkCenter] = null then null else [OperationWorkCenter] = [ClockWorkCenter]),
    #"Added Custom1" = Table.AddColumn(#"Changed Type2", "AfterOperationEnd", each if [ActualEndDate] = null then null else [WorkDate] > [ActualEndDate]),
```

**Check:** SameWorkCenter is null where either name is missing, and AfterOperationEnd is null where there is no end date.

**Watch for:** a test with no null guard. In M an equality with a null is false, not null, so a line with no operation reads as a disagreement: the count of the latest year is 8 lines high, 20 over all the years. In DAX, a measure that tests `= FALSE ()` also takes a blank for false, which is why the model answer's measures use the strict `==`.

### Requirement (4): The counts and the matrix

**Step 4. Load, relate and measure.**

a. Choose **Home > Close & Apply**, and in **Model view** relate LaborPaths[WorkDate] to Date[Date].
b. Add the measures below to **Key Measures**, with the display folder `Ex 15.6`, together with Path Hours and Lines on Both Paths.

```dax
Path Lines = COUNTROWS ( LaborPaths )
Disagreeing Lines = CALCULATE ( [Path Lines], LaborPaths[SameWorkCenter] == FALSE () )
Share After Operation End = DIVIDE ( CALCULATE ( [Path Lines], LaborPaths[AfterOperationEnd] == TRUE () ), [Path Lines] )
```

**Step 5. Build the page.**

a. Add a page named `Ex 15.6` with a **Table** by Year of the lines on both paths, the disagreeing lines and their hours, filtered to direct manufacturing time. The model answer titles it "Direct lines whose two work centers disagree".
b. Add a **Matrix** with OperationWorkCenter on **Rows**, ClockWorkCenter on **Columns** and Path Hours as **Values**, filtered to direct time, the year 2026, and the operations that are not blank. The model answer titles it "Direct hours of 2026: operation's work center (rows) against the time clock's (columns)".

**Check:** the disagreements by year are in the Expected results. The row of Packing Work Center reads 4,325.76 hours clocked at Assembly Work Center, and 26 percent of its hours sit off the diagonal.

**Watch for:** the matrix turned over. Assembly operations clocked at Packing read 295.49 hours, a small cell, and the student concludes Packing is rarely misrecorded. A matrix with no filter on LaborType adds a (Blank) row of 54,323.5 hours of indirect and non-manufacturing time.

### Requirement (5): The shares

**Step 6. Compare on a named denominator.** Among the 3,137 disagreeing lines of 2026, 2,243 (71.5%) were recorded after the operation's end. Among all 13,913 direct lines it is 5,823 (41.85%); among the 13,905 lines on both paths it is 41.88%. The 8 direct lines with no operation cannot be tested. Accept either denominator when the student names it. The disagreement is concentrated in the late time of Chapter 12.

**Check:** the share of all direct lines is proved by the Checks tab, with the eight untested lines.

![The two routes from one labor line to a work center, which the exercise compares.](../figures/chapter-15-management-reports/IF-15-6-B.pdf)

### Requirement (6): The indirect hours and the conclusion

**Step 7. Place the indirect time and decide.** The operation path leaves the indirect hours blank, and the clock places them: Assembly (16,830.0), Finishing and Test (9,561.6), Cutting (7,477.9). The operation path says what work the time was charged to; the clock path says where the time clock placed the employee. Neither alone supports the Packing finding, which needs corroboration (Chapter 12).

**Instructor check.** In **DAX query view**, run this and compare it with the Expected results.

```dax
EVALUATE ROW ( "Disagreeing lines 2026", CALCULATE ( [Disagreeing Lines], LaborPaths[LaborType] = "Direct Manufacturing", 'Date'[Year] = 2026 ), "Share after the end", CALCULATE ( [Share After Operation End], LaborPaths[LaborType] = "Direct Manufacturing", 'Date'[Year] = 2026 ), "Untested lines", CALCULATE ( [Path Lines], LaborPaths[LaborType] = "Direct Manufacturing", 'Date'[Year] = 2026, ISBLANK ( LaborPaths[AfterOperationEnd] ) ) )
```

## What a strong answer says

- **(4)** Disagreements by year with the denominator named, and Packing as the work center whose operations are most often clocked elsewhere.
- **(5)** The late share of the disagreeing lines against all direct lines, with the denominator named, and the link to Chapter 12.
- **(6)** The operation path answers what the time was charged to, the clock path where the time clock placed the employee, and neither supports the Packing finding alone.

A strong answer names what each record cannot show. A weak one declares one path correct.

## Common mistakes and how to respond

- **An inner join.** *Symptom:* 51,097 lines in LaborPaths. *Response:* ask what a line with no operation becomes.
- **A blank read as a disagreement.** *Symptom:* 3,145 disagreeing lines for 2026. *Response:* ask what a test should return when one side is missing.
- **The matrix turned over.** *Symptom:* a small cell read as Packing's. *Response:* ask which axis is the operation.
- **Disagreement called lateness.** *Symptom:* "the lines that disagree are the late ones". *Response:* ask the late share of the disagreeing lines in 2024: 8.5%.
- **One path declared right.** *Symptom:* a verdict on Packing. *Response:* ask what each record measures.
- **No filter on labor type.** *Symptom:* a (Blank) row of 54,323.5 hours. *Response:* ask which lines have an operation at all.
