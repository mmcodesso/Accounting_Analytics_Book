## Purpose and learning outcomes

Before the report is shared, the internal auditor reviews the model the way Chapter 12 reviewed queries: by testing what each relationship does to the numbers. The auditor does not change the model. The queries change a relationship for one calculation with CROSSFILTER, so the effect of Both is visible without being left in. The exercise makes the chapter's Watch out concrete: a two-way filter on a model with two fact tables carries a selection from one into the other. The analytics type is diagnostic.

Students can:

- count one thing three ways and say which count a report should use (Requirement 1);
- show a two-way filter leaking from sales into the ledger (Requirement 2);
- compare a share built with REMOVEFILTERS with one built with ALL on the fact table (Requirement 3);
- write a review list of settings with the test that reveals each (Requirement 4).

**Competencies practiced.** CPA Evolution Core S2 M4 (information technology and IT controls) and BAR M10 (advanced data analytics: data models and joins, dashboards); IMA Data Analytics and Insights (data governance) and Reporting and Control (internal control); IFAC IES 2 (i) (judging the adequacy of information and communications technology processes and controls) and IES 4 (a) (professional skepticism and professional judgment); AACSB A5 part 5.1.

## Step-by-step solution

### Requirement (1): Three counts of customers

**Step 1. Run the printed query.**

a. In **DAX query view**, open a new query tab and rename it `Ex 14.5`.
b. Type or paste the query from the exercise, select it and choose **Run**.

```dax
// Customers by item group, fiscal 2026, counted three ways
DEFINE
    MEASURE Customer[Customer Rows] = COUNTROWS ( Customer )
    MEASURE Customer[Customers Invoiced] =
        DISTINCTCOUNT ( SalesInvoiceLine[CustomerID] )
    MEASURE Customer[Customer Rows Both] =
        CALCULATE (
            COUNTROWS ( Customer ),
            CROSSFILTER ( SalesInvoiceLine[CustomerID], Customer[CustomerID], BOTH )
        )
EVALUATE
SUMMARIZECOLUMNS (
    'Item'[ItemGroup],
    TREATAS ( { 2026 }, 'Date'[Year] ),
    "Customer Rows", [Customer Rows],
    "Customers Invoiced", [Customers Invoiced],
    "Customer Rows Both", [Customer Rows Both]
)
```

**Check:** one row for each item group, with a year filter of 2026 from TREATAS.

| Item group | Customer Rows | Customers Invoiced | Customer Rows Both |
|---|---:|---:|---:|
| Accessories | 220 | 188 | 188 |
| Furniture | 220 | 190 | 190 |
| Lighting | 220 | 187 | 187 |
| Services | 220 | 19 | 19 |
| Textiles | 220 | 181 | 181 |

Customer Rows is the Customer table, which a selection on Item or Date never reaches, because the filter flows from Customer to the lines and not back. Customers Invoiced is the distinct count on the fact table, the one a report should use. Customer Rows Both equals it: with Both, the lines filter Customer. The report uses the distinct count because Both gives the same answer here and changes every other measure that uses the relationship. **Watch for:** adding the groups. They sum to 765, against 209 customers in the year, because customers buy from several groups.

### Requirement (2): The leak into the ledger

**Step 2. Write the second query.** Students write it from the exercise's words: Operating Expense by item group, with CROSSFILTER on the relationship between InvoiceDate and Date, and the dates left in Date.

```dax
EVALUATE
SUMMARIZECOLUMNS (
    ROLLUPADDISSUBTOTAL ( 'Item'[ItemGroup], "All Groups" ),
    TREATAS ( { 2026 }, 'Date'[Year] ),
    "Operating Expense", [Operating Expense],
    "Operating Expense Both", CALCULATE ( [Operating Expense], CROSSFILTER ( SalesInvoiceLine[InvoiceDate], 'Date'[Date], BOTH ) ),
    "Dates Left", CALCULATE ( COUNTROWS ( 'Date' ), CROSSFILTER ( SalesInvoiceLine[InvoiceDate], 'Date'[Date], BOTH ) )
)
```

**Check:** Operating Expense without the change is $6,471,696.58 in every group. With Both:

| Item group | Operating Expense with Both | Dates left |
|---|---:|---:|
| Accessories | $6,285,069.07 | 355 |
| Furniture | $6,426,770.19 | 360 |
| Lighting | $6,117,912.10 | 355 |
| Textiles | $5,855,785.92 | 325 |
| Services | $1,570,297.47 | 12 |
| All groups | $6,471,696.58 | 365 |

The Services figure is the operating expense of the twelve days on which design services were invoiced, a number with no meaning: a selection in the sales star has filtered the ledger through the shared Date table, as the Watch out on two fact tables warns. **Watch for:** a query with no year. Operating Expense then reads $18,860,921.62, the three years, in every row, and the comparison stops being a test of the setting.

### Requirement (3): Two shares

**Step 3. Write the third query.** It shows each group's share with `REMOVEFILTERS ( 'Item' )` (the measure Share of Revenue) and with `ALL ( SalesInvoiceLine )`, and a row for the total.

```dax
EVALUATE
SUMMARIZECOLUMNS (
    ROLLUPADDISSUBTOTAL ( 'Item'[ItemGroup], "All Groups" ),
    TREATAS ( { 2026 }, 'Date'[Year] ),
    "Share REMOVEFILTERS", [Share of Revenue],
    "Share ALL", DIVIDE ( [Revenue], CALCULATE ( [Revenue], ALL ( SalesInvoiceLine ) ) )
)
```

**Check:**

| Item group | REMOVEFILTERS | ALL ( SalesInvoiceLine ) |
|---|---:|---:|
| Accessories | 6.29% | 2.17% |
| Furniture | 58.46% | 20.12% |
| Lighting | 20.16% | 6.94% |
| Services | 4.08% | 1.40% |
| Textiles | 11.02% | 3.79% |
| All groups | 100.00% | 34.42% |

The first column adds to a whole and is each group's share of the year. The second adds to 34.42%, the share of fiscal 2026 in the $86,446,845.84 of three years, because ALL on the fact table removes the year as well. **Watch for:** a student who reads the total as a data error. The function is not at fault; the table it clears is.

### Requirement (4): The review list

**Step 4. Write the list.** Each item has its test:

| Look for | Test that reveals it |
|---|---|
| A relationship set to Both | Compare a count with and without CROSSFILTER (Step 1) |
| A count taken from a dimension or header table | Compare it with the distinct count on the fact table |
| ALL on a fact table inside a share | The shares must total a whole (Step 3) |
| An inactive relationship used without USERELATIONSHIP | A measure that equals its active twin (Exercise 14.2) |
| (Blank) members | Count the keys that find no match |
| Measures that keep the closing entries | The control totals of Exercise 14.6 |

**Instructor check.** In **DAX query view**, run these rows from the Checks tab.

```dax
EVALUATE ROW ( "Services, Operating Expense with Both", CALCULATE ( [Operating Expense], CROSSFILTER ( SalesInvoiceLine[InvoiceDate], 'Date'[Date], BOTH ), 'Date'[Year] = 2026, 'Item'[ItemGroup] = "Services" ), "Dates left, all groups", CALCULATE ( COUNTROWS ( 'Date' ), CROSSFILTER ( SalesInvoiceLine[InvoiceDate], 'Date'[Date], BOTH ), 'Date'[Year] = 2026 ) )
```

## What a strong answer says

- **(1)** The three counts, why the first is constant, and the choice of the distinct count on the facts.
- **(2)** The Services row as the proof: the ledger's figure follows the sales selection, so the setting changes what other measures mean.
- **(3)** What each total is a share of, and that the fact table's ALL removes the year.
- **(4)** Each setting with a test, in the memo's own words, and the point that a test must be repeatable.

A strong answer gives a test for each item. A weak one lists settings to avoid.

## Common mistakes and how to respond

- **Both as harmless.** *Symptom:* "Customer Rows Both equals Customers Invoiced, so it is fine". *Response:* ask what Requirement 2 showed for the ledger.
- **Customer Rows as customers served.** *Symptom:* 220 in every group. *Response:* ask which customers bought in 2026.
- **The groups added.** *Symptom:* 765 customers. *Response:* ask whether a customer can buy in two groups.
- **No year in the query.** *Symptom:* Operating Expense of $18,860,921.62. *Response:* ask which filter fixes the year.
- **The total of the ALL column read as an error.** *Symptom:* a data complaint. *Response:* ask what the denominator holds.
- **A review list of preferences.** *Symptom:* "avoid Both". *Response:* ask what test would show it.
