# Figure brief: draw the figures of one unit of the instructor guides

You build the figures of **one unit** (a chapter `1`..`19`, a case `case1`..`case4`, or an appendix `appB`, `appC`) of *Accounting Analytics: An Integrated Approach*. The unit is named in your instruction. Each figure is declared by a guide template; you write its generator, build it, look at the image, and fix it until it matches its description and the standard. Then stop and report.

Read first: this brief, then `CLAUDE.md` (project instructions: the figure design standard, the verified interface labels, the data rules), then the pilot modules in `scripts/figures/instructor/` as examples of the three styles: `fig_01.py` (a data-driven flow), `fig_07.py` (a chart), `fig_06.py` (an Excel/Power Query mock), `fig_10.py` (a DB Browser mock), `fig_11.py` (a decision tree) and `fig_14.py` (a Power BI Model view). Read `kit.py` (the layout primitives) before you write anything.

## What a figure is

A placeholder in a guide (`{{ figure('IF-06-1-A') }}`) is declared in the template's front matter (`facts/instructor/guides/<unit folder>/<file>.md`): `id`, `kind` (`excel-mock`, `sql-mock`, `pbi-mock`, `diagram`, `chart`), `purpose`, `shows` (what is on screen, in detail) and `data`. Your generator is a function returning a `drawio.Diagram`, registered in `scripts/figures/instructor/fig_<code>.py` as `FIGURES = {"IF-06-1-A": function}` (code: `06` for Chapter 6, `C1` for Case 1, `AB` for Appendix B; lowercase in the file name: `fig_06.py`, `fig_c1.py`, `fig_ab.py`). `build_instructor.py` writes the Draw.io source to `facts/instructor/figures/<unit folder>/<id>.drawio`, exports the vector PDF (Draw.io's cropped PDF, as the book exports `visuals/pdf`) to `instructor-notes/figures/<unit folder>/<id>.pdf`, and records both in `instructor-notes/figures/manifest.json`. `guides.py render` then links the PDF in place of the placeholder, and `guides.py pdf` places it in the PDF notes.

## Workflow

1. `python facts/instructor/guides.py figures --unit U` prints every declaration of the unit in full. Read the guide text around each placeholder (`facts/instructor/guides/<folder>/*.md`) so the figure shows what the guide says, and the guide's context (`python facts/instructor/guides.py context KEY` lists the values; the template's front matter names the key).
2. Write `fig_<code>.py` (create it, or extend it if it exists). Take values from the guide's own context with `ctx.values("ch06.g1")` (the same numbers the guide prints), or from the dataset with `ctx.data()` (a `facts.db.Data`: window `F, P, C, N`, `q()`, `one()`, read-only) or `data.q`. Never type a dataset value (amount, count, date, ID, year) into a generator when a query or a context can supply it: figures must re-render after the yearly roll.
3. Build: `python scripts/figures/instructor/build_instructor.py --unit U` (or `--figure IF-06-1-A`; `--force` to export again). A figure that raises is reported and the rest still build.
4. **Look at every figure** (`instructor-notes/figures/<folder>/<id>.pdf`, open it with the PDF viewer: the Read tool shows a PDF page as an image) and compare it with its `shows` text. Fix, rebuild, look again. What to check: text clipped, wrapped badly or overlapping other text; arrows that do not connect or cross text; a label hidden behind a shape; numbers that disagree with the guide; empty or crowded areas; a legend where color or line style carries meaning; the title and caption lines the figure needs and nothing else. Expect two or three rounds for a complicated figure.
5. `python scripts/figures/check_figures.py --src-dir facts/instructor/figures/<folder>` must report 0 problems (860 px frame, at most 980 px tall, Helvetica, nothing under 12 px, palette colors only, contrast 4.5:1).
6. `python facts/instructor/guides.py render --unit U` and `check --unit U` must stay clean (the check confirms each image has a manifest entry and a source). `python scripts/figures/instructor/build_instructor.py --verify --unit U` reports no problem.
7. Report.

## The figure style

- **The book's standard:** a fixed 860 px frame with a white background; Helvetica; 13 px body text, 14 px bold headers, **nothing below 12 px**; the palette only (ink `#2C3E50`; dark fills with white text: blue `#1A5276`, teal `#117A65`, gray `#5D6D7E`, coral `#B03A2E`, amber `#8A5D00`; light tints with ink text; `#F39C12` highlight with ink text; `#D5D8DC` borders); lines at least 1.5 px; solid gray within a group or process, **dashed amber** for a posting to the ledger or the source-document trace; meaning never by color alone (pair it with a label, line style, weight or symbol).
- **No embedded titles** in a figure unless the picture needs one (a chart's own title, a window's title bar). Notes below a figure are short italics in gray (`size=SMALL, color=GRAY`) and say what is outlined or marked.
- **Mocks** draw an interface faithfully to the book's own mocks: Excel with `excel.py` (title bar, formula bar, sheet, Table view, tabs, buttons, emphasis outlines), DB Browser with `dbbrowser.py` (`execute_sql` runs the displayed SQL read-only to fill the grid and count), Power BI with `powerbi.py` (window, canvas, cards, charts, table and matrix visuals, slicers, Model view, DAX query view). Use only interface labels that the book's tutorials or `CLAUDE.md` give as verified; where the description asks for something unverified (a pane, a dialog), draw only what the guide itself says and list it in your report. The alt text of a mock begins "A mock of ..." (the guide macro adds it).
- **Diagrams and charts** use `kit.py`: `flow` (boxes and arrows, row or column, optional per-box widths), `board` (columns of cards), `decision_tree`, `timeline`, `matrix`, `Plot` (axes, gridlines, bars, points, lines, bands, reference lines), `callout`, `legend`; and `drawio.Diagram` directly (`box`, `text`, `arrow`, `edge` with `exit`/`entry` points, `table`, `grid`, `marker`, `outline`) for anything else. `powerbi.line_chart/column_chart/bar_chart/combo_chart/waterfall_chart` also work for a plain chart. Add a primitive to `kit.py` only when two figures need it; extend it additively and keep `tests/test_instructor_figures.py` passing.
- **Size and legibility:** the figure must be readable at about 800 px wide on screen and printed at page width. Prefer fewer, larger elements to many small ones. A figure 400-600 px tall is typical; never above 980.

## Practical notes (from the pilot)

- Text width: `check_figures.text_width(html, size, bold)` estimates a label's width; `kit.height_for(text, width)` its height. Clip long cell text with an ellipsis (`fig_06._clip`) rather than letting it wrap in a grid row; leave about 22 px of margin in a cell.
- `Diagram.box` labels are HTML: use `<br>` for a break and `<b>` for bold; wrap data values with `esc()` when they could contain `<` or `&`. An edge label with `<br>` works too.
- An edge label sits on the line with a white background; keep the gap between boxes at least as wide as its text (two-line labels like `5<br>shipments` fit a 54 px gap).
- Orthogonal arrows between boxes in a row are straight when you pass `exit=(1, 0.5), entry=(0, 0.5)`; to fan several arrows into one wide box, give each an `entry=(x_fraction, 0)` that matches its source's center.
- `Plot.categories` with empty labels draws an unlabeled bar chart; `Plot.hline`/`band` take values in the axis's units; put a label for a reference line in a white `box` in clear space, not over bars.
- `powerbi.relationship(..., dashed=True)` draws an inactive relationship.
- A statement a figure makes about the data (for example "the joined total is nearly twice the header total") must be computed in the generator from the same numbers it draws.
- Draw.io exports one figure at a time and can take 5-10 s each; do not run two builds at once. If an export fails, rebuild that figure once more.

## Guide edits allowed

You may change a placeholder's `purpose`, `shows` or `data` in your unit's templates when the built figure honestly differs from the first description (for example when DB Browser can show only one result grid), or remove a placeholder and its `{{ figure('ID') }}` line when a picture adds nothing (then also delete its generator). Nothing else in a guide.

## Hard limits

- Edit only: `scripts/figures/instructor/fig_<code>.py` (and, additively, `kit.py`), the figure declarations and `{{ figure() }}` lines of your unit's templates, and the generated files (`facts/instructor/figures/`, `instructor-notes/figures/`, the rendered `instructor-notes/<folder>/`). Do not touch the book's text, `visuals/`, the book's figure modules (`scripts/figures/*.py`, `chNN.py`, `powerbi.py`, `excel.py` and the rest), other units' generators, `datasets/`, or anything else.
- No Excel, no Power BI Desktop, no browser, no git commands, no other agents. Run Draw.io only through `build_instructor.py`.
- Never put a figure source in `visuals/src` (the site build exports and publishes that folder).

## Final message (under 350 words)

- figures built (count of the unit's declared) and total image size in KB;
- any placeholder reworded or removed (id and why);
- unverified interface elements a figure assumes;
- context keys or dataset queries used that a roll could break;
- `check_figures`, `render`, `check` and `--verify` results;
- anything the next unit's agent should know (a kit primitive added, a pattern that worked).

## Lessons from finished units

- `kit.flow` sets 13 px text in boxes about 110 px wide, so a 14-character document number wraps; draw such boxes directly at 12 px (`d.box(..., size=SMALL)`) or give the node more width.
- An edge label leaves dash fragments around it on a dashed arrow: put a white `d.box` label over the edge instead.
- For an arrow that starts inside a multi-cell shape (a grid, a table), use `d.container(x, y, w, h)` as the source so the line does not cross the cells.
- Avoid ": " in the YAML `shows` or `purpose` text of a declaration (it breaks the parse); quote the value if it needs one.
- A figure that mocks a worksheet should show the worksheet row numbers, the column letters and the filter state the guide describes; hide columns the guide does not need and say so in the italic note.
- A Table's banding follows its visible rows, so a filtered Table alternates from its first row; an unfiltered gap view bands by sheet row parity (`_grid_rows(..., band=)` and `_check_columns`/`_hidden_text` in `fig_02.py` handle both and keep worksheet column letters and the "columns hidden" note from the schema).
- Do not anchor orthogonal edges to anchor points for stop marks (they jog): use `meta="edgeStyle=none;"`. Put edge labels beside or above the arrow, not on it, when the gap is short.
- A horizontal chain of six or more document boxes cannot carry key labels in 860 px: use a vertical chain with the ledger box on the right and the labels beside the arrows. Variable-height Excel rows: call `xl.sheet` once per row with `show_letters=False`. A dotted join line needs `meta="dashed=1;dashPattern=2 4;"` (dashed amber means the trace). A label on a dashed arrow can hide it when the gap is narrow: draw the label as text above the line (`_above` in `fig_03.py`).
- A hatched bar (a pattern as well as a color) is drawn by clipping diagonal edges to the bar (`_hatch` in `fig_c1.py`). For orthogonal edges between rows of different tables, give `relate(..., points=[...])` explicit runs. PowerShell has no heredocs: edit files with the Edit tool.
- `fig_04.py` has reusable Excel pieces to copy: `_sheet` (rows of any height, `span` for text overflowing into empty cells, data bars, filter and funnel buttons, wrapped HTML labels), `_slicer`, `_gap`, `_fit`, a formula bar with markup and the `_mark` outline. A BLUE outline vanishes on a BLUE Table header: use TEAL or CORAL. Draw.io wraps a cell's text when it sits within about 12 px of the cell width: pad column widths by 20 or more, or `_clip` will cut the text. The guide macro lowercases only a leading "The"/"A"/"An" of a mock's purpose, so start a mock's purpose with "The".
- Patterns that worked in `fig_05.py`: tables stepped down one row so each foreign key lines up with its primary key, with lookup arrows routed over the tops through `points`; a struck-through `<s>` label in a white box over an edge; two outline groups inset 1.5 px so adjacent outlines do not touch; `kit.lines_for` to size a legend label's height. A text cell starting with a digit is right-aligned unless you pass `align="left"`.
- `_sheet(..., spacing=2 or 3)` and `_box` in `fig_06.py` give dense grids narrower columns; `nowrap()` keeps document numbers from breaking at hyphens. Use `kit.Plot(title=None)` plus your own title text (a Plot title collides with the top tick label); chart labels are white-backed text boxes so gridlines do not strike through them; leave headroom above the highest bar and room below the lowest.
- Give a key color real area (a filled coral tag, not a 4 px dot), so it still reads at small size. `kit.Plot.hline` and `.line` on a categorical plot are shifted half a slot right and `hline` ends outside the plot: pass x from -0.5 to N-0.5. Sixty short `plot.line` segments show gaps at their joints: `_polyline` in `fig_07.py` draws one edge through waypoints (`edgeStyle=none;rounded=0;`). A numeric-x `Plot` filling the full 860 px overflows at its last tick label: use a width of 840 or less.
- Wide workpapers: draw two panes of one worksheet (A to F, then "after scrolling right"). `_wrap(text, width, lines)` in `fig_08.py` cuts a sentence at N lines with an ellipsis, as a fixed-height cell shows it; `_nb()` puts non-breaking spaces in "Exercise 8.5, requirement (6)". Text over gridlines needs a white-filled `d.box`, not `d.text`. `kit.decision_tree` is top-down: draw a left-to-right tree by hand with straight arrows. Read the model-answer workbook with openpyxl in read-only mode (never Excel) to match layouts and wording.
- SQL mock pattern (`fig_09.py`): `_mock` uses `db.window/editor/results/message` with `selection=` and `first_line=` and returns the grid geometry; `_solution` parses a model-answer script (any `Ex N.M.sql`), so the figure shows exactly the quoted query with its real line numbers; `_widths`/`_clip` fit result columns to the frame (cell padding 20); `_outline_lines` boxes editor lines (inset so adjacent outlines do not touch). A long unbreakable token widens a Draw.io label past its box: hand-draw a tree whose nodes need different widths; write references like "Tutorial 9.2, Step 6" with non-breaking spaces inside each part.
- `fig_10.py` helpers worth copying: `_widths` ends with `_fit` (rounded widths could push the grid to 861 px), `_mock(..., shown=slice)` draws a scrolled grid keeping row numbers, `blank_rows` draws an empty result, `_ordinal`, `_word`, `_date` (no-break ISO dates), `_column` (outline a result column). The chooser `IF-10-0-A` is a left-to-right layout (a tall root box with straight arrows to question boxes, each leading to a leaf).
- `fig_11.py` `_mock` options: `lines=` scrolls the editor, `setup=` runs views (`_temp_view(n, name)` turns the script's CREATE VIEW into a TEMP view on the read-only connection), `edit=`/`comment=` draw a variant query, `shown=` scrolls the grid, `tight=` gives cell spacing 3 and a 32 px row-number column, `panes=` draws a result wider than the frame in two panes, `room=` keeps outlines from clipping at 860 px. Charts reuse `_polyline` with a `dashed` option and `_dot` for markers.
- `fig_12.py`: `_keyword_box` outlines a single keyword inside an editor line; `_column(color, inset)`, `_cells` and `_row(color)` give outlines of different colors that stay apart; a band behind bars uses `d.vertex(... fillOpacity=70)` so gridlines still show; value labels over bars: `valign="bottom"` at `y-22`.
- `fig_c3.py`: `_Views("SurgeDays", ...)` is a context manager that creates the model script's views as TEMP views and drops them afterwards; `_mock(..., cols=slice)` draws a grid scrolled right; `_memo_table()` and `_exhibit_makers()` parse the memo structure from the case text and the Requirement 6 guide. `_clip` takes `size` as its third argument: pass `margin=` by keyword. Measure label boxes with bold `text_width`, or the labels wrap.
- Power BI mock pattern (`fig_13.py`): read names, titles, columns, relationships, query order and Checks rows from the solution project's text files and take values from `ctx.values(...)` or the notes' `lines()`; assert each drawn claim against the dataset. Reuse `powerbi.py` for the window, canvas, Model view, DAX editor and simple charts (the pilot `fig_14.py` and `fig_13.py` show the calls). `fig_13.py` has local helpers for what `powerbi.py` lacks: `_frame` (a one- or two-line title), `_table_visual`, `_hbars` (data labels, a selected bar), `_columns`, `_lines_chart`, `_pie`, the Power Query editor header with a type icon, and a scrolled results grid with a scroll bar. A page mock is just canvas plus `page_tabs`. Use white-backed labels and one-pixel gridlines (`_grid_line`) so gridlines do not strike through text. Keep text boxes about 20 px wider than the text, or `check_figures` flags them. Use the Edit tool for patches (the shell rejects apostrophes in heredocs).
- `fig_14.py`: `_editor` is a DAX query view editor that accepts gap rows with true line numbers, a selection band and the update count; `_lane` draws labeled straight arrows between boxes; a waterfall on a truncated axis works with `kit.Plot` plus floating `d.box` bars and an edge-based dashed reference line; wide grids fit more easily when the Data pane is dropped.
- `fig_15.py` helpers: report pages `_table_visual` (per-column `aligns`, no totals), `_slicer_list`, `_tabs(active, d, y)`, `_frame`; Model view `_rel` (relationship with 1 and * tags placed away from the bends, optional jump arcs, `one_tag=False` for shared ends); project readers `_page`, `_hidden`, `_visual`, `_title`, `_folder_measures`, `_table_measures`, `_query_order`; the truncated-axis waterfall with split half-bars and a variance arrow in `if_15_0_d` and the badge cards in `if_15_0_c` are patterns that worked. Where the engine cannot supply a result (a forecast, a visual calculation) draw a band without numbers.
- `fig_15.py` additions: `_table_visual(head_lines=)`, `_slider`, `_cards_visual`, `_matrix` (one level, with outline and fill hooks), `_polyline`. To size a canvas around right-hand callouts or tables, run a "probe" pass on a throwaway `Diagram` first (IF-15-6-A); `kit.height_for` does the same for callouts (IF-15-5-A). Where the engine cannot supply a forecast, the dashed `BLUE_TINT` band plus an amber "Not drawn" callout worked.
- `fig_16.py`: `_columns` and `_combo` leave gaps for blank months, `_year_matrix` (years over repeated value columns), `_vaxis`. To avoid shell heredocs with apostrophes, write a batch of figure functions to a file with the Write tool and append it to the module with a short Python script that also registers the figures.
- `fig_c4.py`: `_matrix` (group headings, `framed=False` for multi-pane visuals, `expanded` markers and indents, bold and rule rows), `_waterfall` (wrapped category labels under negative steps), `_camel_break` (breaks a long heading at a capital), `_combo2`, `_scrollbar`. A heading with a long word needs `d.text`, not `d.box` (box padding overflowed "Conversion"); draw a matrix's header rule after its rows or white cells half-hide it; header-width clipping needs a margin of about 8 for `d.text` (cells use more); the largest page mocks need 20 px rows to stay under 980 px, so check the figure height against the note's height, not only the canvas.
- `fig_17.py`: `_editor` is the book's editor with a 42 px gutter (four-digit line numbers) and a tab as wide as the file name (`db.editor` fails `check_figures` on both); `_mock` overrides the title-bar path to `CharlesRiver_Capstone.sqlite`, cuts long comment lines with an ellipsis, `_Views` creates TEMP views; `_ws` is the Excel sheet function with a 26 px clip margin and numeric cells never clipped (give numeric columns text width plus 24; `&nbsp;` for leading-space indents); for a timeline with clustered dates draw an enlarged strip in a dashed panel with one down arrow from the zoomed stretch; for a Power BI page run a throwaway `draw(Diagram("probe"))` first to size the canvas; `guide_contexts.ch17.cached()` reads the model workbook's saved values.
- `fig_18.py`: workbook access `_cached()`/`_book(sheet)` read saved values (openpyxl, never Excel) and `_agree(ws, ref, value)` asserts a drawn value against its cell; `_g()` gives the guide helpers and `_model()` the notes' `model(d)`; Excel mocks `_ws`, `_wrapped`, `_outline`, `_formula_bar`, `_gap`, `_tabs(d, y, active, names)`, `_acct`, `_clip`, `_wrap` (`if_18_4_a` shows how they fit); charts `if_18_3_b` (grouped bars on `kit.Plot` plus an amber callout arrow) and `if_18_0_b` (to-scale bars with a bracket and legend), `_label`, `_dot`, `_diamond`, `_hollow`, `_polyline`; case text parsers `_requirements`, `_tools`, `_milestones`, `_tool_files`, `_case_text`.
- `fig_18.py` second-half helpers: `_excel_format` and `_show(ws, ref)` (a cell as Excel shows it, from its number format), `_num`, `_head` (wrapped bold header), `_row_of`, `_formula_of` (clipped, non-breaking), `_key` (outline-swatch key), `_runs` (outlines for consecutive rows), `_bar`. A worksheet wider than 860 px works as hidden columns (real letters skipped), a gap band for omitted rows and an italic note saying "narrower than the workbook's"; a block needing a wider column A can be drawn as a second `_ws` fragment under a gap band that says so; draw value labels inside bars with a box of the bar's own fill so contrast checks pass.
- `--figure IF-19-1` also matches IF-19-10-*: pass full ids to select one figure. `fig_19.py` helpers: Excel `_cached`/`_book` (a temp copy of the workbook), `_agree`, `_show`, `_num`, `_ws`, `_outline`, `_formula_bar` (wider Name Box for long names), `_tabs`, `_gap`, `_wrapped`, `_key`, `_row_of`, `_formula_of`; context access `_g()` and `_n()`; case text `_requirements`, `_tools`, `_milestones`, `_tool_files`, `_tag`; Power BI `_page_ids`, `_page`, `_visual`, `_title`, `_projections`, `_query_tabs`, `_expected(label)`, `_page_tabs`, `_frame`, `_table_visual` (`row_fills`, `head_lines`, `total`), `_year_matrix`, `_cards`, `_lines_chart`, `_hbars`, `_scrollbar`; small `_day`, `_date`, `_us_date`, `_badge`, `_label`, `_polyline`.
- `fig_19.py` second-half pieces: wrap cut text with a width margin of at least 28 (`_cut_head`, `_cut_cell`); a table heading turned to read upward is a Draw.io style (`horizontal=0`, `_vhead`); labels on dashed or crossing lines need white-backed boxes.
- `fig_ab.py`: a result grid wider than the DAX window works as two stacked panes with repeated anchor columns and horizontal scroll bars; wrapping cells in white-space:nowrap stops Draw.io wrapping a clipped value; a text box can quote the project's own paragraphs, cut to a few lines each; a decision tree can be drawn with explicit waypoint arrows and white Yes/No boxes laid over the line; a DAX editor can show gap rows with true line numbers.
