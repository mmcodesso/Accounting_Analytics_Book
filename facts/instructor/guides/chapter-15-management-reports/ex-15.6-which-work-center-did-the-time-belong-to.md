# Exercise 15.6: Which Work Center Did the Time Belong To?

{{ header() }}

## Purpose and learning outcomes

The plant page assigns each direct labor line to the work center of the operation it was charged to. The time clock records a work center too, and an auditor does not act on a work-center chart until the two records of the same fact have been compared. The exercise is a data-quality test built in Power Query and DAX, and it ties back to Chapter 12's finding that direct time is recorded after its operation ended. The analytics type is diagnostic, with the judgment that follows a test: say what each record can and cannot support.

Students can:

- import a second source for the same fact and merge it without losing lines (Requirements 1 and 2);
- write tests that return a blank when there is nothing to compare (Requirement 3);
- count disagreements by year and lay them out as a matrix (Requirement 4);
- compare shares on a named denominator, and relate the result to Chapter 12 (Requirement 5);
- decide which record answers which question (Requirement 6).

**Competencies practiced.** CPA Evolution Core S2 M8 (audit evidence and tests of controls) and ISC M4 (use and management of data); IMA Data Analytics and Insights (data literacy) and Reporting and Control (internal control); IFAC IES 2 (f) (audit) and IES 4 (a) (professional skepticism and professional judgment); AACSB A5 part 5.1.

## Before you assign

- **Files.** The copy after Tutorial 15.3. The model answer holds the queries OperationPaths and ClockPaths (**Enable load** cleared) and LaborPaths (loaded), the measures of the display folder Ex 15.6 and page Ex 15.6. LaborPaths reads every labor line, so its refresh takes minutes: tell students before they start.
- **Data conditions.** LaborTimeEntry has {{ g.n_all|count }} lines. Direct lines carry an operation except {{ g.n_blank }} (a few with no operation key, the rest with a key no operation holds); indirect and non-manufacturing lines carry none. Every line has a clock entry, and each work center has its own name, so comparing names gives the answer comparing keys would. The {{ g.n_blank }} direct lines with no operation all have a clock work center.
- **Verify first.** The WorkCenter query exists with WorkCenterName (Tutorial 15.3), and the Date relationship pattern is clear: the model answer relates LaborPaths[WorkDate] to Date, so Year works.

## How to run it

Individual, about 100 minutes: 15 for the two imports, 25 for the merges and names, 10 for the tests, 15 for the measures and matrix, 15 for Requirement (5), 10 for (6), 10 spare. Hold back the null guards until a student's count of disagreements is a few lines high, and the Chapter 12 link until Requirement (5). Collect the .pbix and the note.

### Requirement (2): The merges

**Step 2. Import the labor lines and merge each path.**

a. Import **T60_LaborTimeEntry** as `LaborPaths` and keep LaborTimeEntryID, WorkOrderOperationID, TimeClockEntryID, WorkDate, LaborType, RegularHours and OvertimeHours. Set WorkDate to **Date**.
b. Choose **Home > Merge Queries** and merge with OperationPaths on WorkOrderOperationID, with a left outer join. Expand WorkCenterID and ActualEndDate without the prefix, and rename WorkCenterID `OperationWorkCenterID`.
c. Merge with ClockPaths on TimeClockEntryID the same way, expand WorkCenterID, and rename it `ClockWorkCenterID`.
d. Merge each of the two keys with the **WorkCenter** query to bring the name, as `OperationWorkCenter` and `ClockWorkCenter`.

```m jinja
{{ g.m_merges }}
```

**Check:** LaborPaths keeps all {{ g.n_all|count }} lines, because every merge is a left outer join; a line with no match keeps a null.

**Watch for:** an inner join. LaborPaths then holds {{ g.n_inner|count }} lines: the indirect and non-manufacturing lines, and the direct lines with no operation, are gone, and Requirement (6) has no indirect hours to place.

### Requirement (3): The two tests

**Step 3. Add the custom columns.** Choose **Add Column > Custom Column** twice, and set both to a true or false type.

```m jinja
{{ g.m_tests }}
```

**Check:** SameWorkCenter is null where either name is missing, and AfterOperationEnd is null where there is no end date.

**Watch for:** a test with no null guard. In M an equality with a null is false, not null, so a line with no operation reads as a disagreement: the count of the latest year is {{ g.blank_now|count }} lines high, {{ g.n_blank|count }} over all the years. In DAX, a measure that tests `= FALSE ()` also takes a blank for false, which is why the model answer's measures use the strict `==`.

## What a strong answer says

- **(4)** Disagreements by year with the denominator named, and Packing as the work center whose operations are most often clocked elsewhere.
- **(5)** The late share of the disagreeing lines against all direct lines, with the denominator named, and the link to Chapter 12.
- **(6)** The operation path answers what the time was charged to, the clock path where the time clock placed the employee, and neither supports the Packing finding alone.

A strong answer names what each record cannot show. A weak one declares one path correct.

## Common mistakes and how to respond

- **An inner join.** *Symptom:* {{ g.n_inner|count }} lines in LaborPaths. *Response:* ask what a line with no operation becomes.
- **A blank read as a disagreement.** *Symptom:* {{ (differ + g.blank_now)|count }} disagreeing lines for {{ g.y }}. *Response:* ask what a test should return when one side is missing.
- **The matrix turned over.** *Symptom:* a small cell read as Packing's. *Response:* ask which axis is the operation.
- **Disagreement called lateness.** *Symptom:* "the lines that disagree are the late ones". *Response:* ask the late share of the disagreeing lines in {{ g.by_year[0].year }}: {{ g.by_year[0].share_late_differ|pct(1) }}.
- **One path declared right.** *Symptom:* a verdict on Packing. *Response:* ask what each record measures.
- **No filter on labor type.** *Symptom:* a (Blank) row of {{ g.non_direct|num(1) }} hours. *Response:* ask which lines have an operation at all.
