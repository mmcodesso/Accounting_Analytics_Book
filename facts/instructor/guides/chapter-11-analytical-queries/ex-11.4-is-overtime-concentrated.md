# Exercise 11.4: Is Overtime Concentrated?

{{ header() }}

## Purpose and learning outcomes

The plant manager's first answer to the controller's finding is that overtime is a problem of a few people, not of the plant. The exercise tests that claim with the time records of the latest year. It uses a ranking function and a running share, an aggregate window that needs the right frame, and a half-page memo that answers a claim with evidence. The analytics type is diagnostic: it locates the overtime without naming a cause.

By the end, students can:

- total overtime by employee with a join and a date range, using the work date (outcomes 1 and 3);
- rank the employees and build a running share with `ROWS UNBOUNDED PRECEDING` over a total from `OVER ()` (outcome 3);
- find the rank at which the share passes one half, and summarize by job title (outcomes 3 and 4);
- answer a claim in a memo, and say what the totals do not show.

**Competencies practiced.** CPA Evolution Core S1 M8 T3 to T4 (data mining and analysis of financial data); IMA Data Analytics and Insights (data analysis) and Business Acumen and Operations (operational knowledge); IFAC IES 2 (b) and (i); AACSB A5 part 5.1.

## Step-by-step solution

### Requirement (1): Overtime by employee

**Step 1. Total each employee's overtime for the year, with the job title.**

```sql
-- Requirement (1): fiscal 2026 overtime hours by employee, by work date, with the job title
-- Population: manufacturing labor time of 2026; expected: 64 employees
SELECT lt.EmployeeID, e.JobTitle,
    ROUND(SUM(lt.OvertimeHours), 1) AS OvertimeHours
FROM LaborTimeEntry AS lt
    INNER JOIN Employee AS e ON e.EmployeeID = lt.EmployeeID
WHERE lt.LaborType <> 'NonManufacturing'
    AND lt.WorkDate BETWEEN '2026-01-01' AND '2026-12-31'
GROUP BY lt.EmployeeID, e.JobTitle
HAVING SUM(lt.OvertimeHours) > 0
ORDER BY OvertimeHours DESC, lt.EmployeeID;
```

**Check:** {{ g.n }} rows, employee {{ top[0][0] }} first with {{ top[0][2]|num(1) }} hours, and a total of {{ total|num }} hours. **Watch for:** four variants change the result without an error.

- `strftime('%Y', lt.WorkDate) = {{ year }}` compares text with a number and returns {{ g.n_num|count }} rows.
- Keeping only `LaborType = 'Direct Manufacturing'` returns {{ g.direct_n }} employees and {{ g.direct_total|num }} hours, because indirect overtime is left out.
- Dropping the LaborType filter adds non-manufacturing time: {{ g.all_n }} employees and {{ g.all_total|num }} hours.
- The HAVING condition removes nobody here ({{ g.no_having }} rows without it), but it belongs in the query for a year in which someone has none.

### Requirement (2): The ranking and the running share

**Step 2. Rank the employees and add the running share.**

```sql
-- Requirement (2): the employees ranked, with a running share of all overtime
-- Population: the employees with overtime; expected: the running share reaches 1.000
WITH Overtime AS (
    SELECT lt.EmployeeID, e.JobTitle,
        SUM(lt.OvertimeHours) AS OvertimeHours
    FROM LaborTimeEntry AS lt
        INNER JOIN Employee AS e ON e.EmployeeID = lt.EmployeeID
    WHERE lt.LaborType <> 'NonManufacturing'
        AND lt.WorkDate BETWEEN '2026-01-01' AND '2026-12-31'
    GROUP BY lt.EmployeeID, e.JobTitle
    HAVING SUM(lt.OvertimeHours) > 0
),
Running AS (
    SELECT EmployeeID, JobTitle, OvertimeHours,
        RANK() OVER (ORDER BY OvertimeHours DESC) AS OvertimeRank,
        ROW_NUMBER() OVER (ORDER BY OvertimeHours DESC, EmployeeID)
            AS RunningRank,
        SUM(OvertimeHours) OVER (ORDER BY OvertimeHours DESC, EmployeeID
            ROWS UNBOUNDED PRECEDING)
            / SUM(OvertimeHours) OVER () AS RunningShare
    FROM Overtime
)
SELECT EmployeeID, JobTitle, ROUND(OvertimeHours, 1) AS OvertimeHours,
    OvertimeRank, ROUND(RunningShare, 3) AS RunningShare
FROM Running
ORDER BY RunningRank;
```

**Check:** {{ g.n }} rows, the running share of the last row is 1, and the first employee holds {{ top[0][2]|num(1) }} hours of {{ total|num }}. **Watch for:** the running order must be deterministic. The model uses EmployeeID as a tie-breaker and `ROWS UNBOUNDED PRECEDING` to make the row-by-row intention explicit. With that unique full order the default frame gives the same result, even when two overtime totals tie, because peers are the rows tied on every ORDER BY column. Ordered by OvertimeHours alone, tied totals are peers and the default frame takes the whole tied group at once, so keep the unique tie-breaker when the question asks for a minimum number of employees. No two totals tie in {{ year }}, so a student who orders by the total alone gets the same shares here, but not necessarily on another year. RANK itself would give tied employees one number; the model script adds a ROW_NUMBER with EmployeeID so the running order is stable.

### Requirement (3): Half of the overtime

**Step 3. Find the rank where the share reaches one half.** The model script keeps the running rows in a CTE and returns `MIN(RunningRank)` where `RunningShare >= 0.5`, with the number of employees and the total beside it.

**Check:** {{ half }} of {{ g.n }} employees account for half; the share is {{ g.before_half|pct }} one employee earlier and {{ g.at_half|pct }} at that rank. **Watch for:** ordered from the lowest total instead, {{ g.asc_half }} employees are needed, one more; the question is how few employees carry half, so order from the highest.

### Requirement (4): By job title

**Step 4. Total the overtime and average it per employee by job title.**

```sql
-- Requirement (4): overtime hours and the average per employee by job title
-- Population: the employees with overtime; expected: 3 job titles
WITH Overtime AS (
    SELECT lt.EmployeeID, e.JobTitle,
        SUM(lt.OvertimeHours) AS OvertimeHours
    FROM LaborTimeEntry AS lt
        INNER JOIN Employee AS e ON e.EmployeeID = lt.EmployeeID
    WHERE lt.LaborType <> 'NonManufacturing'
        AND lt.WorkDate BETWEEN '2026-01-01' AND '2026-12-31'
    GROUP BY lt.EmployeeID, e.JobTitle
    HAVING SUM(lt.OvertimeHours) > 0
)
SELECT JobTitle, COUNT(*) AS Employees,
    ROUND(SUM(OvertimeHours), 0) AS OvertimeHours,
    ROUND(AVG(OvertimeHours), 1) AS AveragePerEmployee
FROM Overtime
GROUP BY JobTitle
ORDER BY OvertimeHours DESC;
```

**Check:** {{ titles|length }} job titles: {% for t in titles %}{{ t[0] }} {{ t[1] }} employees, {{ t[2]|num }} hours{{ "; " if not loop.last else "" }}{% endfor %}. **Watch for:** averaging the entries instead of the employees' totals gives about an hour, between {{ g.entry_low|num(2) }} and {{ g.entry_high|num(2) }}, the average time entry; the question is hours per person.

## What a strong answer says

- **The claim is not supported.** Half of the overtime is reached at rank {{ half }} of {{ g.n }}, the middle of the list; the five largest hold {{ g.top5|pct }} and the ten largest {{ g.top10|pct }}, and the running share climbs almost in a straight line. A concentrated pattern would reach half within a handful of names.
- **The spread is even across jobs.** The averages by job title are nearly the same, {{ mean|num(1) }} hours for each employee who recorded overtime over the year's records. Spread over 52 weeks that is about {{ weekly }} hours a week, an equivalent rather than a measured weekly average, because the direct records end on {{ direct_end }} and the indirect records on {{ indirect_end }}.
- **The period, stated once.** A memo that counts both kinds of time only to {{ g.ind_end }} has {{ g.c_total|num }} hours and reaches half at rank {{ g.c_half }}, and it gives the same answer. Accept it when the memo names the cut-off.
- **What the totals do not show.** A plus. They show the distribution, not the cause. Before naming one, a strong memo asks about staffing and demand, how overtime is approved and how time is captured, and points to Chapter 12, which tests the surge days and the hours paid beyond the work.
- **Name the basis.** The memo states that the year is cut by work date and that the payroll year gives {{ payroll|num }} hours.

A weak memo says the claim is false without a figure, or explains the overtime by something the query cannot show.

## Common mistakes and how to respond

- **A year compared as a number.** *Symptom:* {{ g.n_num|count }} rows. *Response:* ask what type strftime returns.
- **Only direct time.** *Symptom:* {{ g.direct_total|num }} hours. *Response:* ask which labor types are manufacturing.
- **Non-manufacturing time included.** *Symptom:* {{ g.all_n }} employees. *Response:* ask what the filter was for.
- **A nonunique running order.** *Symptom:* none on this data, which has no tied totals. *Response:* ask whether tied employees should be accumulated together or one by one, and whether the reported minimum headcount is deterministic.
- **Ordering from the lowest.** *Symptom:* {{ g.asc_half }} for half. *Response:* ask what the question counts.
- **Averaging entries.** *Symptom:* about an hour for every title. *Response:* ask what one row of the table is.
- **A memo without the basis.** *Symptom:* hours that differ from Chapter 10's. *Response:* ask which year definition each uses.
