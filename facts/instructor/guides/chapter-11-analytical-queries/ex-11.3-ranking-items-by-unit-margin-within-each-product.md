# Exercise 11.3: Ranking Items by Unit Margin Within Each Product Line

{{ header() }}

## Purpose and learning outcomes

The product manager wants to know which items earn the most per unit at list price within each product line, and how wide the range is. The controller wants a ranking that can be refreshed when prices or standard costs change. The exercise puts the three ranking functions side by side, keeps the top of each group with a CTE and an outer filter, and uses window functions where GROUP BY would collapse the detail. It ends with a managerial judgment: what a margin at list price does and does not measure. The analytics type is descriptive, with a diagnostic caution.

By the end, students can:

- calculate a unit margin and a margin percentage, and rank within groups with RANK, DENSE_RANK and ROW_NUMBER (outcome 3);
- say when the three functions differ, and keep the top rows of each group with an outer filter (outcomes 3 and 4);
- show a group's range beside every item with a window, and say why a margin at list price is not a contribution margin (outcomes 3 and 6).

**Competencies practiced.** CPA Evolution BAR M5 (cost accounting and variance analysis) and Core S1 M8 T3 to T4 (data mining and analysis of financial data); IMA Reporting and Control (cost accounting) and Data Analytics and Insights (data analysis); IFAC IES 2 (b) and (i); AACSB A5 part 5.1.

## Step-by-step solution

### Requirement (1): The unit margin

**Step 1. Calculate the margin and the margin percentage for the priced items.**

```sql
-- Requirement (1): the unit margin at list price and the margin percentage
-- Population: items with a list price; expected: 223 items
SELECT ItemGroup, ItemCode, ItemName, ListPrice, StandardCost,
    ROUND(ListPrice - StandardCost, 2) AS UnitMargin,
    ROUND(100.0 * (ListPrice - StandardCost) / ListPrice, 1) AS MarginPct
FROM Item
WHERE ListPrice IS NOT NULL
ORDER BY ItemGroup, UnitMargin DESC;
```

**Check:** {{ items }} rows. **Watch for:** without `ListPrice IS NOT NULL` the query returns {{ g.n_all|count }} rows, {{ g.n_unpriced }} with a NULL margin, from groups the product manager does not sell; NULL sorts last in a descending order, so the damage hides at the foot of each group.

### Requirement (2): Three rankings

**Step 2. Rank within each item group three ways.** The model script puts the margins in a Margins CTE and the ranks in a Ranked CTE, and names the window once.

```sql
-- Requirement (2), step 1: RANK, DENSE_RANK, and ROW_NUMBER within each item group
-- Population: items with a list price; expected: the three agree when no margins tie
WITH Margins AS (
    SELECT ItemGroup, ItemCode, ItemName, ListPrice, StandardCost,
        ROUND(ListPrice - StandardCost, 2) AS UnitMargin,
        ROUND(100.0 * (ListPrice - StandardCost) / ListPrice, 1)
            AS MarginPct
    FROM Item
    WHERE ListPrice IS NOT NULL
),
Ranked AS (
    SELECT ItemGroup, ItemCode, ItemName, UnitMargin, MarginPct,
        RANK() OVER w AS MarginRank,
        DENSE_RANK() OVER w AS MarginDenseRank,
        ROW_NUMBER() OVER w AS MarginRowNumber
    FROM Margins
    WINDOW w AS (PARTITION BY ItemGroup ORDER BY UnitMargin DESC)
)
SELECT ItemGroup, ItemCode, UnitMargin, MarginPct, MarginRank,
    MarginDenseRank, MarginRowNumber
FROM Ranked
ORDER BY ItemGroup, MarginRank;
```

**Step 3. Count the items whose rankings differ.** The next query counts `MarginRank <> MarginRowNumber OR MarginDenseRank <> MarginRowNumber` over Ranked.

**Check:** {{ items }} rows, and zero items whose rankings differ, because no two items in a group share a margin. **Watch for:** the explanation students need is when they would differ, and this data does not show it. Ranked by the rounded margin percentage instead, the three functions disagree on {{ g.differ }} of the {{ items }} items, and RANK keeps {{ g.top3_rank }} rows for the top three where ROW_NUMBER keeps {{ g.top3_row }}, because the {{ g.services }} Services items all tie at a full margin.

### Requirement (3): The top three of each group

**Step 4. Keep the top three with an outer filter.** The query reads the Ranked CTE and adds `WHERE MarginRank <= 3`; the model script returns {{ g.top3_row }} rows, three for each of {{ g.n_groups }} groups.

**Check:** the first row of each group is the item of the Expected results. **Watch for:** the filter cannot sit in the SELECT that calculates the rank: SQLite stops with `{{ g.msg }}`, and the wording differs a little between versions. Students who rank in a derived table or CTE and filter outside have it right.

### Requirement (4): The group's range beside every item

**Step 5. Add the highest, the lowest and the count with windows.**

```sql
-- Requirement (4): each group's highest and lowest unit margins and items, beside every item
-- Population: items with a list price; expected: 223 rows, each with its group's range
WITH Margins AS (
    SELECT ItemGroup, ItemCode, ItemName, ListPrice, StandardCost,
        ROUND(ListPrice - StandardCost, 2) AS UnitMargin,
        ROUND(100.0 * (ListPrice - StandardCost) / ListPrice, 1)
            AS MarginPct
    FROM Item
    WHERE ListPrice IS NOT NULL
)
SELECT ItemGroup, ItemCode, UnitMargin,
    MAX(UnitMargin) OVER (PARTITION BY ItemGroup) AS GroupHighest,
    MIN(UnitMargin) OVER (PARTITION BY ItemGroup) AS GroupLowest,
    COUNT(*) OVER (PARTITION BY ItemGroup) AS GroupItems
FROM Margins
ORDER BY ItemGroup, UnitMargin DESC;
```

**Check:** {{ items }} rows, each with its group's range, so the windows run over every priced item, not only the top three that Step 4 keeps. **Watch for:** `GROUP BY` returns {{ g.n_groups }} rows and loses the items; a window with no PARTITION BY returns one range for the whole table on every row; and a MIN with `ORDER BY UnitMargin DESC` inside OVER runs only to the current row, so GroupLowest reads each item's own margin on all {{ items }} rows.

## What a strong answer says

- **When the rankings differ.** RANK gives ties one rank and skips the numbers after them, DENSE_RANK gives ties one rank without a gap, and ROW_NUMBER numbers every row, breaking ties in an order the query does not control. They can differ when a group contains ties, both at the tied rows and at later rows: RANK leaves a gap after a tie, while DENSE_RANK does not. Over the values 100, 90, 90 and 80, RANK gives 1, 2, 2, 4 and DENSE_RANK gives 1, 2, 2, 3. All three agree here on the unit margin, where no group has a tie; a percentage rounded to one decimal shows the difference.
- **Why Services shows its price.** Services items are design work whose StandardCost is zero, because their cost is the design staff's payroll, which posts to operating expense and not to inventory. Their margin equals their price.
- **Why this is not a contribution margin.** The manufactured items' StandardCost includes fixed overhead, which does not change with one more unit; the measure leaves out discounts, price lists and promotions, so list price is not the price charged; and it leaves out variable selling costs such as commissions and outbound freight. For pricing or product mix the manager needs variable cost and net price.

A weak note calls the ranking a profitability ranking, or says the three functions are the same.

## Common mistakes and how to respond

- **No ListPrice filter.** *Symptom:* {{ g.n_all|count }} rows and groups with NULL margins. *Response:* ask which items the manager sells.
- **Ranking by the rounded percentage.** *Symptom:* disagreeing ranks and {{ g.top3_rank }} rows for the top three. *Response:* ask what RANK does with ties.
- **A rank filtered in the same SELECT.** *Symptom:* the `misuse of` error. *Response:* ask when WHERE runs.
- **A MIN or MAX with an ORDER BY in OVER.** *Symptom:* a group's lowest margin equal to the item's own. *Response:* ask which rows the default window reads.
- **GROUP BY for the range.** *Symptom:* {{ g.n_groups }} rows and no items. *Response:* ask what the exercise says about keeping the detail.
- **The range of the top three only.** *Symptom:* a range and a count taken after the top-three filter, so each group shows three items. *Response:* ask which items the range should describe.
- **Margin called contribution.** *Symptom:* a note with no limits. *Response:* ask what the cost includes.
